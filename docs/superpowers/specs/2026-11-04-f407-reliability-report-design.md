# F407 本地可靠性报告设计

- 日期：2026-11-04
- 状态：设计已获用户确认，等待设计稿复核
- 范围：现有 F407 本地 MQTT 仪表板的浏览器端历史面板

## 目标

在已有历史时间线、存储覆盖范围和 ACK 延迟摘要之上，增加一份容易演示和解释的可靠性概览。它回答“这段观测时间里 Wi-Fi/IP 与 MQTT 有多稳定”，并明确指出浏览器没有采到数据的时间。

不新增硬件、固件接口、服务端数据库、网络请求或第三方依赖；数据仍留在当前浏览器配置文件的 IndexedDB 中。

## 用户可见行为

- 提供最近 **1 小时、6 小时、24 小时**三个时间范围，默认 24 小时。
- 分开展示 Wi-Fi/IP 与 MQTT：已知观测时长、观测在线比例、明确记录的掉线次数；只有断开和恢复都被完整观测时才显示掉线时长。
- 显示 ACK 结果数量，以及有匹配命令计时数据的 ACK 延迟 P95。界面不把收到的 ACK 数量称为命令成功率。
- 将数据缺口和“最近已知”状态单独标出。保留的 Broker 快照不会伪装成在线/离线转变。
- 保留现有历史列表和事件 CSV，不新增报告导出格式。

## 指标口径

统计窗口为从当前时间向前选定时长的闭区间，按浏览器接收时间排序。Wi-Fi/IP 只使用实时状态记录；STA 已连接且具有有效 IPv4 才算“网络就绪”，明确断开或缺少有效 IP 算未就绪，unknown 不算离线。MQTT 在线证据来自实时 online availability 或实时设备状态，离线证据来自实时 offline availability。保留快照只用于显示当前最近已知状态。

报告只把相邻实时观测间隔不超过 **2 分钟**的区间计入已知时长。此阈值是现有每分钟稳定状态采样周期的两倍；更长的间隔、窗口内第一个实时观测之前和最后一个实时观测之后都计为未知，不外推在线状态。观测在线比例为已知在线时长除以已知时长；已知时长为零时显示“样本不足”。掉线次数只计窗口内从已观测在线转为离线的明确转变；掉线时长仅统计有明确恢复且中间没有未知区间的完整事件，窗口从离线状态开始、或未闭合的事件不估算时长。

ACK 延迟 P95 只用已匹配命令和会话的数值样本，按最近秩法计算：升序排列后取索引 `ceil(0.95 × 样本数) - 1`。未匹配 ACK 仍按收到的结果分类，但不参加延迟统计。若历史存储降级到仅内存，报告注明当前页面记录可能不完整。

## 验收标准

1. 覆盖完整在线、完整掉线后恢复、超 2 分钟缺样、窗口边缘缺样、仅有 retained 快照五种数据；未知区间不得算作在线或掉线时长。
2. Wi-Fi/IP 与 MQTT 的比例和事件数分别计算；没有足够实时证据时显示样本不足。
3. ACK P95 与匹配的数值延迟一致；未匹配 ACK 不污染延迟结果。
4. 选择时间范围后只重算本地历史，不发 MQTT 命令、不请求设备，也不改变现有命令流程。

## 非目标

不添加浏览器通知、云端监控、设备端日志、自动故障修复、长期审计或物理 LED/蜂鸣器反馈测量。
