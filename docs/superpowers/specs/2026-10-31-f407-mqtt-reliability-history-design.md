# F407 本地 MQTT 可靠性历史面板设计

- 日期：2026-10-31
- 状态：设计已获用户确认；实现与代码复核修正已完成，30 项离线测试通过
- 范围：现有本机 MQTT 仪表板的浏览器端历史记录功能

## 目标与现状

仪表板目前能显示设备最近一次状态、在线状态和最近 ACK，但刷新页面后，短时事件历史无法继续查看。增加本地历史面板，帮助演示和排查 Wi-Fi/MQTT 断线、状态变化、遥测丢失及命令确认延迟。

只在运行仪表板的浏览器本机保存记录。项目不新增硬件，不改 STM32/ESP 固件，不增加云端服务，不新增第三方依赖。

## 用户可见行为

历史面板提供：

- Wi-Fi/IP 与 MQTT availability 两条独立时间线，避免把“连上 Wi-Fi”显示成“MQTT 在线”。
- LED、蜂鸣器 GPIO 回读、设备会话/序号和遥测丢弃计数的状态变化记录。
- 稳定状态的每分钟采样点，用于确认长时间运行期间仍持续收到状态。
- MQTT 在线/离线变化、命令 ACK 结果及可测量的 ACK 延迟。
- 当前保留的记录数、最早记录时间、覆盖时长，以及因容量上限丢弃的记录数。
- CSV 导出。导出文件只包含仪表板已有的状态和 ACK 元数据，不包含 Wi-Fi 密码或原始串口/网络负载。

历史属于当前浏览器配置文件和仪表板来源。换浏览器或清除该站点数据后，历史不共享也无法恢复。

## 存储与保留

使用浏览器 IndexedDB 持久保存结构化历史。无需新依赖。

- 仅保留最近 24 小时的数据。
- 总记录数最多 5,000 条。
- 清理在页面启动和新记录写入时执行；超出任一限制时优先删除最旧记录。
- 若事件量使 5,000 条不足以覆盖完整 24 小时，界面显示实际最早记录时间与实际覆盖时长，不把它描述成完整 24 小时。
- 记录以浏览器接收时间（UTC）作为时间线时间；保留设备启动会话 ID 与 seq，用于排序、去重和识别重启。
- 页面导出与查询先按接收时间排序；同一设备、同一启动会话的 state/snapshot 槽位再按设备 seq 排序，availability/ACK 等无序号事件保留接收时间顺序。容量与覆盖范围始终按接收时间计算。

### 记录类型

每条记录包含类型、设备 ID（若适用）和浏览器接收时间；需要去重的记录可带内部去重键。

1. state：Wi-Fi/IP、LED/蜂鸣器 GPIO 回读、会话 ID、可选设备 seq、丢弃快照计数及状态来源。兼容缺少 seq 的历史或旧版状态时，只用于显示和历史，不允许远程控制。
2. availability：MQTT online/offline 变化和 Broker 观察时间。
3. ack：会话 ID、命令 ID、命令类别、执行结果、GPIO 回读及 ACK 延迟（若可匹配）。
4. storage：仅在本地记录存储错误或恢复状态，供界面解释历史不完整；不写入异常堆栈、路径或其他敏感环境信息。

## 采集、去重与指标

- 收到实时状态变化时立即记录；状态未变化时每分钟最多采样一次。两个条件同时满足时合并为一条记录，并标记变化与采样原因。
- 同一会话和 seq 的 QoS 重投只记一次。没有 seq 的状态按规范化指纹抑制连续 2 秒内的重复投递，仍保留真实状态变化，并每分钟采样一次稳定状态。无 seq 状态只用于显示和历史，不允许远程控制；序号显示“未知”。
- Broker 保留消息标记为“最近已知快照”。可以在每次页面运行中记录一次当前快照；同一页面内重复投递去重，页面重新打开时重新记录当前快照。快照不计作实时在线/离线转换、实时新鲜度恢复或设备状态变化，也不据此推算 ACK 延迟。
- ACK 仅在命令 ID 和启动会话 ID 同时匹配当前待确认命令时计算延迟。延迟从该命令首次发布到匹配 ACK 被浏览器收到；同 ID 的有限重发不会创建新的延迟起点。重复 ACK 不重复计数。
- F407 的丢弃快照累计值只在同一启动会话内比较。新会话的首条状态建立新基线；只有计数增加才记录丢弃量，重启造成的计数回零不算负丢弃。
- 时间线把 Wi-Fi/IP 与 MQTT availability 分开呈现；离线后保留的最后状态显示为“最近已知”，不伪装成当前实时状态。

## 查询与导出

历史视图按时间范围读取记录，默认展示最近 24 小时内仍保留的数据。界面展示：

- Wi-Fi/IP 与 MQTT 在线状态的时间线，以及最后实时更新的时间。
- 状态变化、每分钟采样、重启/新会话、丢弃计数变化和命令 ACK。
- ACK 延迟明细与汇总（数量、最小值、中位数和最大值）；没有匹配 ACK 时显示“未知”，不补造数值。
- 可用时间范围和记录容量状态。

CSV 使用 UTF-8，字段按 CSV 规则转义，时间用 ISO 8601 UTC 格式。导出当前实际保留的筛选范围；空值保持为空，字符串字段正确处理逗号、引号和换行。

## 错误处理与数据边界

如果 IndexedDB 不可用、配额不足或写入失败：

- 实时 MQTT 仪表板继续工作。
- 显示明确提示“历史记录未能持久保存”，并说明可能存在缺失区间。
- 当前页面可保留有界内存历史供查看和导出；页面刷新后不承诺恢复这些临时记录。
- 存储失败不触发对 Broker、设备或网络的额外请求，不阻塞 MQTT 消息处理。

历史不用于远程控制、不重发命令、不改变 Broker 保留策略，也不保存密码、Wi-Fi 凭据、原始 MQTT payload、串口数据或完整异常堆栈。

## 验收与离线测试

实现时通过现有前端测试工具覆盖以下情况；本设计阶段不运行测试或构建：

1. 状态变化立即入库，稳定状态每分钟最多记录一次；同一时刻的变化和采样合并。
2. 24 小时过期清理及 5,000 条容量清理均删除最旧记录，并正确显示实际覆盖范围。
3. 同会话/序号的 QoS 重投、重复 ACK 和 retained 快照不会重复污染可靠性指标。
4. 新启动会话重置 seq 时不会被误认为旧事件或负丢弃计数。
5. ACK 延迟只匹配正确的会话与命令 ID；重试沿用同一计时起点。
6. CSV 对引号、逗号、换行、空值和 UTC 时间正确编码，且不包含凭据字段。
7. IndexedDB 不可用或写入失败时，仪表板仍可工作，并显示持久化不可用状态。
8. 现有 MQTT 状态展示、命令流程和设备通信行为保持不变；缺少 seq 的状态仍可显示和记录，远程控制保持禁用。

## 非目标

- 固件、MQTT 协议、Broker、设备命令和网络配置变更。
- 云端存储、账号同步、跨设备共享和身份认证变更。
- 自动修复断线或自动重发控制命令。
- 超过 24 小时或 5,000 条的永久审计日志。
- 证明物理 LED 发光或蜂鸣器实际发声；ACK 仍以 F407 执行结果与 GPIO 读回为准。
